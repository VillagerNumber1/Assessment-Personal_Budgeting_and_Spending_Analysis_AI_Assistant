# 设计说明

> 这份文档对应考核交付物里的「项目文档：方案设计、遇到的问题与解决方式、未完成的部分及原因」。
> 使用说明和接口列表在 [README](../README.md)，排期在 [ROADMAP](../ROADMAP.txt)。

## 1. 目标与边界

**做的是什么**：把「一句话」或「一张小票」变成结构化账目，落到 SQLite，再用统计、查账、预算把它读回来。

```
一句话 / 小票照片 / 账单 CSV·xlsx
        ↓  解析（规则优先，模型兜底；模型只翻译，不算数）
     transactions 表
        ↓
月度统计 · 分类横条 · 近 6 个月趋势 · 自然语言查账 · 预算提醒
```

**明确不做的**（写出来比藏着好）：

- 多用户 / 登录 / 在线部署：单机单用户，`user_id` 在表结构里预留但没有启用
- 手写、严重折叠、反光的小票：认不出就说认不出，不硬猜
- 分类预算：个人只有一个钱包，预算只做月度总额
- 弹窗推送提醒：提醒只走视觉（进度条变色 + 看板娘），不做系统通知

## 2. 架构

```
浏览器（templates/index.html，单文件）
├─ 记账 / 语音 / 小票 OCR / CSV·xlsx 导入
├─ 查账（自然语言 → 展示 DSL）
└─ 统计、预算、预览勾选、操作历史

FastAPI（app.py，只做路由和校验）
├─ parser.py    一句话 → 金额 / 日期 / 时刻 / 类别 / 方向 / AA 人数（纯规则，不联网）
├─ llm.py       两个 prompt：补记账字段、解析查账问句（返回都要过白名单）
├─ query.py     问题 → DSL → SQL（SQL 全部由代码拼，参数绑定）
├─ receipt.py   小票 / 截图 → 金额 / 商户 / 时间（视觉模型，只读不写库）
├─ importer.py  CSV / Excel → 账目草稿（认编码、找表头、去重）
├─ asr.py       语音识别（DeepSeek 云端；本地模型已拆）
└─ storage.py   SQLite：建表、增删改查、统计、操作留痕
```

分层规矩：

- **接口层不写业务**：`app.py` 只负责「收参数 → 校验 → 调下层 → 返回」。
- **模型层不碰数据库**：`llm.py` / `receipt.py` 只吐字段，落库仍然走 `storage.py`。
- **校验独立于来源**：手打、语音、导入、OCR 的数据，最后都要过同一套金额/日期检查。

## 3. 关键设计决策

每一条都写清「为什么这么选」和「代价是什么」。

### 3.1 数字不经过模型

模型只负责把话翻译成字段（金额、日期、类别），统计和金额永远由 SQL / 规则算。
**代价**：规则覆盖不到的说法要模型兜底，多了两次网络调用；**收益**：模型编不出一个不存在的总额。

### 3.2 金额一律用整数「分」

`amount_cents` 存整数，展示时除 100。浮点累加会出现 0.1+0.2≠0.3 这种账对不上的问题。

### 3.3 看不懂就说看不懂

查账时规则认不出的问模型，模型也说「这不是问账」就回「没看懂」，**不兜底成「这个月一共 XX 元」**。
日期模糊（「最近」「上周」）直接拦下让用户换个说法——默默记成今天等于替用户编数据。

### 3.4 软删除 + 操作留痕

删除只打 `deleted_at`，所有查询都带 `deleted_at is null`；增改删恢复写 `operations` 表，
保留 66 天，可撤销。**代价**：每张表都要记得带过滤条件（漏过，查账算进已删的账）。

### 3.5 预算按「生效区间」存

默认预算不是全局字段，而是 `budget_defaults` 里一段段 `[month_from, month_to]`。
改默认值 = 截断旧段 + 开新段，回看老月份还是当时那个数。
**为什么**：全局字段会让 2019 年也套上今天的 3000——历史被后来的设置篡改，跟 `occurred_at` 不该被改是同一条原则。

### 3.6 颜色只有一个源头

`templates/index.html` 的 `:root` 是一套语义变量（`--bg` / `--card` / `--ink` / `--accent` / `--red-soft` …），
组件里一律 `var(--x)`；暗色只改 `[data-theme="dark"]` 里那套值，不再一条条覆盖组件。

**代价**：加新组件时要先想「这个颜色属于哪一类」；**收益**：暗色覆盖规则从 69 条降到 9 条。

暗色下踩过的两个坑（都修了，留在 README 的已知限制里）：分段控件的选中块和凹槽用了同一个变量，
选中块直接消失；开关轨道写死了浅灰，暗色下还是亮的。教训是：

- 变量要按**语义**命名，不能顺手借一个「看起来颜色一样」的
- 删暗色覆盖规则前，先确认组件定义里用的已经是同一个变量

### 3.7 前端单文件

结构 + 样式 + 脚本全在 `templates/index.html`（约 3700 行）。考核原文说「不要把东西全塞进一个文件」，
这里是有意的取舍：Live2D 的生成脚本和页面结构耦合，真拆要动它，交付前风险大于收益。
**代价**：改一处要搜关键词定位；`check_js.py` 之类的自检脚本就是为这个补的。

### 3.8 导入：先预览，再入库

- 解析层（`importer.py`）只干「表 → 行」，读不懂的行跳过并说清第几行、为什么
- 前端把读出来的行**全部列出来**，默认全选，可以筛选、勾选、全选/反选
- 提交时只发勾中的行，但服务端**逐行重新校验**：勾选只是「少导几条」，不是「免检」
- 去重键是 `(记账时间, 金额, 文字)`，只跟没删的账比——删掉再导同一份，应该能重新进来

**代价**：大文件会把所有行传回前端（单机上几百行可接受）；**收益**：导错一列不会几百条一起进库。

### 3.9 小票 OCR：模型只负责读，不负责算

- prompt 里写死「取实付，不是原价、不是找零」，并且**不许按商品单价自己加起来算**
- 读不出金额就整条失败，返回「这张图没读懂」——不拿商品价格凑一个数
- 识别结果塞进现有的编辑框（跟「没听出金额」复用同一个），确认才入库：
  「OCR 读错了」和「人打错字了」走同一条纠错路径
- 上传前在浏览器里缩到长边 2000px；又长又窄的整页账单截图直接拦下（接口单边上限 8192px）

### 3.10 处理队列

写操作（记账 / 语音 / OCR）进一个客户端队列串行执行，查账排在最后。
同时打字、语音、贴图时不会两个流程各弹一个窗；前一件在等用户确认时，后面的老实等着。

## 4. 遇到的问题与解决（挑有代表性的）

| 现象 | 根因 | 解决 |
| --- | --- | --- |
| 「昨天22点打车32」记成 22 元 | 找金额时先命中时间里的数字 | 先 `strip_time()` 把时间剥掉再找钱 |
| 「买了5090显卡」记成 5090 元 | 型号里的数字被当成金额 | 数字打分：后面跟名词降权、句尾加分；分不够就不认金额 |
| 「打车32，我爱蔡徐坤」后半句没了 | 没金额的分句被直接 `continue` | 并进相邻那笔的文字里 |
| 「最近花了多少」默默记成今天 | 模糊日期没有拦截 | 识别出「最近/上周/月底」直接 400，让人换说法 |
| 查 2019 年的账冒出今天的预算 | 默认预算是全局字段 | 改成按月份区间的 `budget_defaults` |
| 微信账单表头不在第一行 | 前面有十几行说明文字 | 扫前 40 行找「同时有时间和金额」的那一行，不固定跳行 |
| 微信导出的 CSV 是 GBK，支付宝带 BOM | 编码不统一 | 先 UTF-8、再 GBK，开头 200 字节有 NUL 就按 UTF-16 |
| xlsx 装不了 openpyxl | 开发环境装包受限 | 用标准库 `zipfile` + `ElementTree` 自己解（共享字符串、日期样式、多工作表） |
| 暗色下分段控件选中块消失 | 选中块用了 `var(--field)`，暗色下跟凹槽同色 | 加语义变量 `--seg-on` |
| 设置弹窗两侧有蓝线 | 输入框的焦点圈比弹窗宽 8px，从半透明遮罩下透出来 | 开弹窗前 `blurComposer()` |
| 小票识别卡在「正在读」 | 无头浏览器里 `createImageBitmap` 不 resolve | 改用 `<img>` + objectURL 解码 |

## 5. 未完成的部分及原因

### 5.1 本地 OCR（评估过，没做）

**动机**：小票、PDF 里有商户名和订单号，图片不出本机当然是隐私亮点。

**为什么没做**：

1. 纯 OCR 只给「字」，不给「哪一行是哪笔、哪个数是实付」；本地 OCR 之后还得自己写行聚类和金额选取，
   整条链路比云端视觉模型**更脆**，不是更稳
2. 只把 OCR 本地化还不够——规则兜底时仍会调云端 LLM；要讲隐私得是「全本地模式」，
   那是一个更大的开关
3. 模型不能进仓库、不能进镜像，首次使用要下载，跟「离线隐私」的卖点有点矛盾
4. 交付前时间要留给测试和文档（考核里「有没有自检手段」「文档是否一致」是实打实的分）

**如果以后做**：选 RapidOCR（onnxruntime，模型十几 MB、CPU 能跑），照 `asr.create_transcriber()`
的工厂模式加 `ocr.create_reader()`，`auto` 先云端失败退本地，默认关；在 20 张真实小票上
金额字段准确率不到 80% 就不许默认开。

### 5.2 长截图 / PDF 账单导入

整页支付宝截图（1152×15644）会被视觉接口拒掉（单边上限 8192px）。
DeepSeek 的 OCR 工具接口（`/v1/tools/ocr`）能吃，但只回纯文本、没有逐行坐标，
同一行的商户/时间/金额会散成多行——要做就得「切块 + 行解析 + 人工勾选」，
正好复用导入预览那条链路。**排期原因**：收益是锦上添花，成本至少一天。

### 5.3 手机直接调后摄

现在手机上点回形针走的是系统给的「拍照 / 相册」选择；要「直接开后摄」只差一个 `capture="environment"`。
没做的原因：桌面端没有后摄，得处理降级，收益是体验而非功能。

### 5.4 其他

- 多用户 / 登录 / 在线 Demo：超出题目要求，`user_id` 已预留
- PDF 账单（有文本层的）本地抽取：思路同 5.2，成本半天
- 前端单文件：见 3.7，写进了 README 的已知限制
