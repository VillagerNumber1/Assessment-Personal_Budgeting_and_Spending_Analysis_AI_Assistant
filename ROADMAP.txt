下一步：小票 OCR + 各种奇形怪状的单据
----------------------------------------------------------------------
  目标
    一张图进来 -> 取出「金额 + 商户 + 时间」-> 显示「我读到了什么」
    -> 用户确认或改 -> 入库。跟语音那条链路同样的节奏：先识别，再确认。

  分工
    - 后端：POST /api/receipt（multipart）-> 调视觉模型 -> 返回结构化草稿
    - 前端：接收文件 -> 展示读到的字段 -> 可改 -> 确认入库
    - 校验复用现有那一层：金额范围、日期格式、类别白名单

  交互照 DeepSeek 那种来做（"拖进去就能认"）
    - 整页可拖入：文件拖到页面任意位置 -> 出现投放区 -> 松手就开始识别
    - Ctrl+V 直接粘贴截图（从微信 / QQ 截图过来，这是最常见的路径）
    - 识别中给个"正在读…"，读完先把字段摊开，用户点确认才入库
    - 失败不要静默：明确说"这张没读懂"，并把光标放回手动输入框

  图不止小票一种，按难易排
    1. 干净小票（白底横排、金额单独一行）—— 先保证这条通
    2. 手机截图（支付宝 / 微信账单详情）—— 金额大、字少，反而好认
    3. 文档类：PDF 账单 / 银行流水导出 / Excel —— 有文本层就直接抽，没有才转图
    4. 手写、折叠、反光的小票 —— 不做，认不出就说认不出

  两条硬规矩（跟现有设计保持一致）
    - 模型只负责「读」，读出来的数字仍要过校验层，不能直接入库
    - 认不出就停下来问人，绝不编一个金额

  降级方案（必须有）
    视觉接口挂了 / 没配 key -> 提示「这张图没读懂，手动记一笔吧」，
    并把光标放回输入框。整条链路不能因为 OCR 不可用而废掉。

  验收
    拍一张便利店小票 -> 上传 -> 金额和时间对得上 -> 改一下商户 -> 入库成功

Docker 自检（不用每次 commit 都跑，跑这三个节点就够）
----------------------------------------------------------------------
  什么时候跑：
    1. 每次「要交出去」的 commit 之前
    2. 改过 Dockerfile / docker-compose.yml / requirements-web.txt 之后
    3. 交付前最后一遍（配合数据卷持久化确认）

  命令（在项目根目录，PowerShell）：
    docker compose build
    docker compose up -d
    curl http://127.0.0.1:8000/api/summary      # 有 JSON 出来就算起来了
    docker compose logs --tail=30               # 看有没有 ImportError
    docker compose down

  最容易挂的四处（都踩过）：
    - 代码加了 import、requirements-web.txt 没加  -> 容器启动 ModuleNotFoundError
    - Dockerfile 用 COPY *.py 而不是手写清单      -> 曾经漏过 query.py
    - 拉基础镜像超时                              -> BASE_IMAGE=镜像加速地址
    - 容器里 pip 连不上源                         -> network: host 已经配好

  已有静态自检：temp_trying/check_docker_deps.py（不装 Docker 也能先看依赖漏没漏）

Docker 是什么（给非计算机专业的人）
----------------------------------------------------------------------
  一个箱子：把 Python、依赖、代码打包进去。
  别人装了 Docker，一条命令就能跑，不用配任何环境。
  你只要写一个 10 行的 Dockerfile，剩下是背命令。

  常用三条：
    docker compose up --build      # 启动
    浏览器打开 http://localhost:8000
    docker compose down            # 关掉
